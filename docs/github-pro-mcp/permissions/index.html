Permissions

Permissions and the tools they unlock

A fine-grained token only needs the permissions for the tools you actually plan to use. The table below maps each permission to the tools that require it.

Permission Level Tools Notes
Metadata read owner_list_repository, repository_search Prerequisite for every repository-scoped tool.
Contents read file_get_content, code_search Code search reads file contents.
Contents write file_create_update, file_delete, pull_request_merge Merging a pull request needs Contents write, not Pull requests write.
Issues read issue_read, issue_list, issue_search, label_list, issue_get_field_value Comments and labels can also be read with Pull requests read.
Issues write issue_create, issue_add_comment, issue_add_label, issue_remove_label, issue_update, issue_close, issue_reopen, sub_issue_write, label_write, issue_set_field_value Comments and labels can also be written with Pull requests write.
Pull requests read pull_request_read Also satisfied by Contents read.
Pull requests write pull_request_create Create a pull request from an existing branch.
Issue fields read owner_list_issue_field, issue_get_field_value, issue_set_field_value, issue_list (with include_fields or filter_fields), issue_read (with include_fields) Organization permission. Populates Priority, Effort and date values.
Issue fields write issue_set_field_value Organization permission. Sets or clears field values.
Issue types read owner_list_issue_type Organization permission.
Projects read owner_list_project, projects_get, issue_list (with include_project_fields or filter_fields) Organization Projects v2. Not the repository Projects permission.
Projects write projects_write Organization Projects v2. Adds items, updates field values and deletes items.
Administration write none of the 34 tools Only the test suite needs this, to create and delete throwaway repositories.
Members read none Optional. No current tool requires it.
No permission required - auth_get_current_login, server_info, profile_get, owner_list_organization, organization_search Authenticated-user or public endpoints. Public search results are readable by any token.
The most common surprise: merging a pull request needs Contents: write, not Pull requests: write. Granting only Pull requests write lets you create a pull request but not merge it.

A few rules worth knowing

  • Metadata read is required by every repository-scoped tool, even when you do not select it explicitly.
  • Issue comments and labels accept either Issues write or Pull requests write.
  • Pull request reads accept either Pull requests read or Contents read.
  • Writing files under .github/workflows/ also needs Workflows write.
  • Organization permissions only exist when the resource owner is an organization.
  • Public search results are readable by any token, which can make a token look broader than it is.
