Configuration

One JSON file.

There is no environment-only mode. Configuration lives in a file; the environment is only a source of secrets, referenced from that file.

Where it is read from

  1. MAILGLASS_CONFIG: an explicit path
  2. ~/.config/mailglass/config.json
  3. ~/.mailglass/config.json

If none exists, the server refuses to start and prints both default paths.

Unknown keys are rejected. A typo like "provder" fails loudly instead of silently falling back to defaults.

Secrets are references

FormExample
Environment{ "env": "WORK_GMAIL_PASSWORD" }
File (chmod 600){ "file": "~/.secrets/work_gmail" }

Never literals, so the config can be shared safely. App passwords are whitespace-stripped: Google shows them as abcd efgh ijkl mnop and the spaces are cosmetic.

Need a Gmail app password?

For Gmail, auth.password points at a Google app password. If you do not have one yet, see Create a Gmail app password, which covers 2-Step Verification, IMAP and where to store the value.

email vs auth.username

email is identity only: what gets displayed and masked. auth.username is what authenticates, and defaults to email when omitted. They differ on many IMAP servers, and for Gmail aliases.

The read-only gate

Resolved per account as account.readOnly ?? provider.readOnly ?? true. When true, write capabilities are withheld entirely; they cannot be registered. Defaulting to true means a config that says nothing can never send or delete mail.

Local storage

KeyDefaultMeaning
storage.dir~/.mailglassBase directory; one subdirectory per account id
storage.cachetruefalse performs no disk writes at all
storage.maxEmlBytes26214400Skip caching larger messages; 0 means unlimited
session.ttlSeconds60Keep an idle connection this long; 0 closes after each call
proxy.urlnonehttp:, https: or socks*: proxy for IMAP

Cached mail is plaintext on disk: directories are 0700 and files 0600. Purge with rm -rf ~/.mailglass/<account-id>.
